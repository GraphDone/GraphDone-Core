# GraphDone state and delivery gaps — 2026-09-07

The product vision is a living, graph-native workspace: easy capture and editing, visible progress, human/agent peers, dependency-driven coordination, requirements traceability, and accessible operation across devices. The source contract is `docs/USER_STORIES.md`, `docs/design/interaction-model.md`, and the clarified [human-first AI workspace](../design/human-ai-workspace.md). A working graph canvas does not establish completion of the entire app.

## Validation scope

- Final type checking: all four packages passed.
- Production build: all four packages passed (existing large-chunk warning).
- Baseline unit tests: Core 41, Server 28, Web 228 passed. MCP run failed with heap exhaustion in the performance-chaos suite; it is not an all-green baseline.
- Web unit suite: 235 tests passed, including recorded-activity determinism/malformed-data tests. New analytics unit tests cover empty graphs, real status accounting, priority ranking and malformed values, contributor identity/deduplication.
- `tests/e2e/graph/responsive-real-workflows.spec.ts` exercises live Neo4j-backed data, filtering, persisted edits, completion and editor bounds at seven desktop/portrait/landscape dimensions. Each fixture is isolated and cleaned up; small-screen runs use touch input.
- Seven headed responsive persistence journeys passed at 320×568, 390×844, 844×390, 768×1024, 1024×768, 1280×720, and 1920×1080. The test now requires SVG nodes to fit inside the viewport, not merely have CSS visibility. Initial camera framing follows settling positions until stable and stops when a person interacts.
- Initial headed phone portrait/landscape screen matrix: 29 passed (28 screens plus auth setup). The expanded seven-resolution sweep ran 99 cases: 98 passed and one Admin contrast failure identified gray text on hover; that contrast has been corrected. Screenshots exposed crowding the earlier page-overflow audit missed; calendar/timeline filters now collapse, dashboard graphics scale, and the landscape header is smaller. This audit still does not prove every control works or every internal region is visually correct.
- Web lint has zero errors and 698 warnings, predominantly existing. No assertion is made that every page or every requirement is finished.

## Delivery priorities

1. Make the hosted persistence and authorization contract correct and cost-bounded.
2. Integrate these responsive/live-data changes and test them against the hosted API.
3. Finish membership, agent, ontology and admin behavior with end-to-end evidence per story.
4. Replace full polling with revision/delta synchronization and a live collaboration service.
5. Keep a release gate covering portrait, landscape, desktop, touch, keyboard, offline/error recovery and reduced motion. Mark a story shipped only when its complete acceptance criteria pass.

## Simplicity pass after product clarification

- Overview now leads with real progress, attention items and current work. Open an item directly from the summary; advanced distributions expand on demand.
- Board defaults to populated status lanes, with an explicit option to show empty lanes. Keyboard users can open cards with Enter or Space.
- A touch tap on a graph item or a desktop click on its edit icon opens quick edit directly. Both native touch events and browser compatibility-click paths are handled. The regression test permits one opening action, with no interaction retries.
- Short-window navigation scrolls instead of stranding account controls below the screen. The project-health toggle no longer covers calendar header actions.
- Admin role reference collapses, low-contrast labels are brighter, and dialogs are viewport-bounded, scrollable, named, focus-contained and dismissible with Escape.
- Latest headed workflow gate: 10 passed (seven direct-edit/persistence sizes, including open-editor rotation, plus three Admin form sizes).
- Local D1-backed frontend progress/persistence journey passed. Core API progress-to-UI journeys passed on phone and desktop. These verify recorded updates, not autonomous execution.
- User direction: visual/UI/UX correctness and fewer actions take priority now. Free open-source Core remains distinct from a future managed product with advanced gateway/autonomous-agent capabilities. See the updated design contract.
